# Cimmich support and triage

Cimmich Community Preview is a small, technically informed testing cohort, not
a hosted support service or stable compatibility promise.

## Before opening an issue

1. Confirm the problem on exact Immich 3.1.0 and the newest Cimmich Community
   Preview.
2. Try the same journey with the fictional Cedar House demo when possible.
3. Search existing issues.
4. Use the issue forms and include only synthetic or redacted evidence.

Never attach real photos, names, document content, credentials, embeddings,
database dumps or private filesystem paths.

## Triage expectations

- Data-loss, Immich-mutation, migration, authentication and unrecoverable
  install/restore reports are triaged first.
- Reproducible Core workflow and accessibility defects come next.
- Optional providers, Guided clients and matching-quality reports are handled
  after Core unless they block the supported lifecycle.
- Maintainers aim to acknowledge a complete reproducible report within seven
  days. This is a target, not a service-level agreement.

Use the private reporting route in [SECURITY.md](SECURITY.md) for suspected
vulnerabilities. Public issues are for ordinary defects and product requests.
